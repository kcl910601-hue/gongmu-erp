# 관리자 직원 목록 배지 개선안

코드 변경 없이 다음 Sprint에서 검토할 UI 설계안이다. 기존 직원 목록의 레이아웃과 행 동작은 유지하고, 현재 조회 중인 `auth_user_id`, `active`, `approval_status`, `role`을 별도 배지 열 또는 이름 아래의 한 줄로 표시한다.

| 항목 | 배지 문구 | 권장 표현 | 판단 기준 |
| --- | --- | --- | --- |
| Auth 연결 | 연결됨 / 미연결 | 연결됨: 초록, 미연결: 회색 또는 주황 | `auth_user_id` 존재 여부 |
| Active | 활성 / 비활성 | 활성: 초록, 비활성: 회색 | `active === true` |
| Approval | 승인 / 대기 / 거절 | 승인: 초록, 대기: 노랑, 거절: 빨강 | `approval_status` |
| Role | Admin / Manager / Staff / Viewer | 기존 역할 색상 체계 재사용 | 표준화된 `role` |

데스크톱에서는 `계정 상태` 열에 Auth → Active → Approval → Role 순으로 배치하고, 좁은 화면에서는 직원 이름 아래에 줄바꿈 가능한 배지 그룹으로 둔다. 색상만으로 상태를 구분하지 않도록 항상 텍스트를 함께 표시한다. 미연결·비활성·대기·거절 상태를 먼저 눈에 띄게 하되, 배지 클릭만으로 상태를 변경하지 않는다.

필터 후보는 `Auth 미연결`, `비활성`, `승인 대기`, `승인 거절`, 역할별 필터다. 목록 상단에는 현재 필터 결과의 상태별 건수만 표시할 수 있다. 실제 구현 전에는 기존 직원 목록 컴포넌트와 Badge 컴포넌트 재사용 여부를 확인하고, API나 DB 스키마는 추가하지 않는다.

접근성 기준은 배지 텍스트 대비 확보, 아이콘 사용 시 보조 텍스트 제공, 상태별 일관된 문구 사용이다. Auth 연결은 계정 존재 여부가 아니라 현재 `employees.auth_user_id` 연결 여부를 뜻한다는 도움말을 제공한다.
